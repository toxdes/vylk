# Zen mode text-editing refactor

In Zen, create a link through the Link action or type complete Markdown in order. Edit the displayed label like ordinary text and use the Link action to change its URL. For direct edits to link syntax, use the existing Markdown editor. Markdown remains the saved document.

## Audit findings

The baseline is `baa9b3e`. The reproductions below use the shipped Zen assets and Chromium keyboard input. Where a case starts with a precise selection, the fixture sets the selection first and sends the subsequent action through the editor. The flows later in this document describe proposed behavior.

The original audit reproduced a caret jump in Chromium and Firefox when filling in a pretyped `[]()`. For example, entering `/docs` between the parentheses produced `[docs](/)`. The renderer hid the destination on the first valid character, and [`domPoint()`](internal/web/static/js/editor/zen-editor.js#L282) mapped the caret into the label. This informs the source-preservation rule below. Filling a link from pretyped brackets and parentheses is outside the Zen interaction contract.

Keep the behaviors already covered in [the browser fixture](test/browser/zen-inline-toolbar.spec.js). Completed syntax hides while typing ordinary prose. Native navigation skips hidden markers. Formatting part of a label preserves one link and its destination. Deleting or replacing a visible range across formatting preserves the unselected fragments. Select All, IME replacement, link popup cancellation, and untouched line identity in large notes also have coverage.

The source also exposes gaps that need targeted browser tests. [Link lookup](internal/web/static/js/editor/zen-editor.js#L315) includes both outer endpoints, which can make a caret beside the link count as an edit of that link. [Copy and Cut](internal/web/static/js/editor/zen-editor.js#L879) copy raw offsets, while Cut deletes by visible range. [The Code action](internal/web/static/js/editor/zen-toolbar.js#L204) detects wrappers from neighboring backticks. [The input handler](internal/web/static/js/editor/zen-editor.js#L796) uses the live selection for replacement, including browser-generated replacement input. Check each against the acceptance cases below.

## Editor references

- **Notion** documents Markdown typing shortcuts, formatting commands on a selection, link creation, and pasting a URL over selected text. Use those interaction patterns for the rich-text path. [Notion keyboard shortcuts](https://www.notion.com/help/keyboard-shortcuts#markdown-style)
- **Obsidian** documents Live Preview, where the cursor can expose the underlying syntax, and Source mode for precise control. Vylk already has a separate Markdown editor for precise source edits. [Obsidian views and editing modes](https://obsidian.md/help/edit-and-read)
- **ProseMirror** represents pending marks in transaction state and uses a non-inclusive link mark in its basic schema. These are precedents for making the next insertion style explicit and for keeping prose typed at the outside edge of a link unlinked. [ProseMirror transactions](https://github.com/ProseMirror/prosemirror-state/blob/master/src/transaction.ts#L18), [ProseMirror basic schema](https://github.com/ProseMirror/prosemirror-schema-basic/blob/master/src/schema-basic.ts#L101)
- **CodeMirror** lets navigation and deletion share a policy for hidden or replaced ranges. Use that principle for hidden Markdown boundaries. [CodeMirror atomic ranges](https://github.com/codemirror/view/blob/main/src/editorview.ts#L1000)
- **CommonMark** allows an empty inline link label or destination, allows emphasis in a label, and prohibits nested links. Zen requires a visible label and an allowed nonempty destination before decorating a link. [CommonMark links](https://spec.commonmark.org/0.31.2/#links), [CommonMark emphasis](https://spec.commonmark.org/0.31.2/#emphasis-and-strong-emphasis), [CommonMark code spans](https://spec.commonmark.org/0.31.2/#code-spans)

The editor comparisons are based on documentation and upstream source. The keystroke results in the audit table come from Vylk.

## Interaction contract

In the examples, `|` marks the caret and is never entered into the note. **Mod** means Command on macOS and Control on Windows and Linux. **Left** and **Right** mean unmodified arrow keys. The examples use left-to-right text. Preserve native visual direction for bidirectional text.

- **Formatted text.** Keep completed markers and destinations hidden during ordinary navigation. Each horizontal arrow crosses one visible grapheme or a line break. Adjacent or nested styles introduce no invisible stops. An arrow that lands at a construct’s outer edge gives the caret outside affinity. Typing there extends the surrounding prose and any outer style that still contains that position.
- **Literal link syntax.** Show incomplete or unsupported links as ordinary editable text. `[]()` has no placeholder, field navigation, or automatic link dialog. Use the plain Markdown editor to work directly in link delimiters and destinations. If a literal edit reparses a link, decoration must preserve the insertion point. Keep the text visible when hiding its syntax would move the active caret into another part of the link.
- **Selection.** Keep anchor and focus separately. Backward selection stays backward through formatting, cancellation, and Undo. A drag, touch selection, or Shift+arrow range over displayed text describes the same content. It must never select a hidden URL by itself.
- **Edits.** Keep source bytes outside the edit and its necessary wrapper repair. Where several Markdown spellings express the same edit, preserve the existing delimiters where possible. Assert exact bytes for unrelated text, URLs, titles, escapes, and line endings. Assert displayed text, styles, and caret behavior where equivalent delimiter spellings are acceptable.
- **Fallback.** Leave incomplete, invalid, unsupported, or context-dependent syntax editable whenever Zen cannot map it reliably. Preview supplies the full document interpretation. Moving the caret and switching between Write and Preview leave the saved source unchanged.

### P1. Create links in Zen

1. Select `Docs` and choose Link. Enter `/docs` and submit. Expect `[Docs](/docs)|`. Type `!` and confirm the exclamation mark appears outside the link. Repeat with a bold or italic selection.
2. In an empty line, type `[Docs](/docs)` character by character, with the closing parenthesis last. Until the closer arrives, the source stays visible. The closer renders the link with the caret outside. Type `!` and expect `[Docs](/docs)!`. Repeat with the link in surrounding prose and with nested formatting in the label. Paste and reopen a complete link to verify the same display.
3. Type or paste `[]()`, `[Docs]()`, `[](/docs)`, and `[Docs](/docs`. Each stays visible as text and round-trips as written. Use ordinary arrows, selection, and deletion on the literal characters. A whitespace-only label also stays literal. In the plain Markdown editor, fill the brackets and destination in either order, then return to Zen to see the completed link.

### P1. Enter, edit, and leave a completed link

1. Start with `x[Docs](/docs)y`. Place the caret visually between `x` and `D`. Right crosses `D` and typing `!` inserts it in the label, producing `x[D!ocs](/docs)y`. From between `c` and `s` in the original, press Right once, then type `!`. Expect `x[Docs](/docs)!y`.
2. At the outside right edge, Left crosses `s`; the next Left crosses `c`. At the outside left edge, Left crosses `x`. Repeat at line and document boundaries, where movement stops at the normal endpoint. For `[A](/a)[B](/b)`, typing at the shared edge inserts plain text between the links.
3. Select the full visible label and replace it. The new label keeps the destination and title. For direct changes to Markdown punctuation or the title, switch to the plain Markdown editor and return to Zen after the edit.
4. Open the existing Link action from a caret strictly inside the label or a selection within it, including the entire visible label. For a one-character link, select the character to target the link even when both endpoints have outside affinity. At a collapsed edge shared by two links, require an explicit selection for Edit Link. Focus and select the URL field. Edit `/docs` to `/updated` in `[**Docs**](/docs "Title")`. After submission, expect `[**Docs**](/updated "Title")` and a caret outside the link on the right. With a bare relative filename already in the source, submitting the unchanged field is a no-op even if the creation form requires a relative prefix.
5. Open the popup on a backward selection. Escape restores its exact anchor and focus. Click-away leaves the clicked caret or control in focus. A snapshot reload, note switch, vault lock, or mode change closes a stale popup. Enter in a stale URL popup cannot edit the new document.
6. Keep current URL validation and error recovery. An invalid submission leaves both source and selection intact and keeps the field available for correction. A blank submission from creation is a no-op. A blank submission on a link intentionally unlinks and keeps the label formatting. Plain click edits text, and modifier-click follows a safe completed link. Literal and unsafe destinations stay inert.
7. Use these destination fixtures for both source edits and the popup where the URL is supported. Check `/docs`, `./note.md`, `#heading`, `?q=a%20b`, `https://example.com/a(b)`, angle brackets, an escaped parenthesis, and a quoted title. Editing one part preserves the other parts. If Zen lacks exact destination coordinates for a construct, use the plain Markdown editor for that change.
8. Distinguish links from surrounding punctuation, escaped brackets, images, code, and references. Try `![alt](/img)`, `\[label](/uri)`, `[nested [brackets]](/uri)`, and `[text][ref]` with a definition elsewhere. An unsupported construct stays editable as source. A destination or title may contain characters that also have meaning inside a label.

### P1. Delete, replace, split, and join

1. At the visible left edge in `x[Docs](/docs)y`, Backspace deletes `x` and Delete deletes `D`. At the right edge, Backspace deletes `s` and Delete deletes `y`. Repeat from both keyboard arrival directions and with bold nested in the label. Removing the final label character removes an otherwise empty completed link. Explicit Unlink remains available through the Link action.
2. In literal link syntax, Backspace and Delete edit the neighboring visible character. In `[Docs]()`, press Backspace just before the final parenthesis. Expect `[Docs])` and a caret before the remaining parenthesis.
3. Replace the selected `oc` in `[D**oc**s](/docs)` with `OO` via typing, paste, and IME. Expect `[D**OO**s](/docs)` in each case. Replace a selection that crosses from the label into following unlinked text. The remaining label fragment keeps its own destination, and the replacement takes only styles shared by the selected visible text. The result contains no orphaned delimiters or undisplayed URL fragment.
4. In formatted text, type a space at the right edge of `**ab**`. Expect `**ab** `. In a revealed source range, typing before the closers edits the Markdown as written, so `**ab **` stays visible as literal text. A prose insertion or selection replacement preserves whitespace and places any trailing space outside a closing emphasis marker when necessary.
5. In `x[Do|cs](/docs)y`, press Enter. Expect `x[Do](/docs)` followed by a newline and `[cs](/docs)y`. Both surviving fragments keep the destination. The caret moves to the start of the second line, before the opening bracket of the second link. At `x[Docs](/docs)|y`, Enter makes a plain line starting in front of `y`. Apply the same split rules to nested emphasis. An ordinary multiline paste uses the same fragment rules. Zen currently inserts a source newline for both Enter and Shift+Enter, so apply these guarantees to both.
6. Join adjacent lines with Backspace at line start or Delete at line end. Joins keep both lines' visible content and avoid delimiter sequences that change styles. If joining fragments of the same link, keep each surviving destination valid. Keep heading, quote, and list markers editable as existing source. Within code blocks, Enter and deletion edit literal code.
7. Test platform word deletion, line deletion, and selection replacement at link and mark boundaries. A visible edit reaches word or line boundaries in displayed content. It cannot count a hidden URL as a word. The same ranges when revealed use the actual source text.
8. Repeat with a combining accent, a family emoji, a flag, an RTL label, and a label split across visual lines. Character deletion and movement respect whole graphemes. Up and Down keep the browser's visual column behavior. Shift movement preserves the anchor and can reverse direction across a style boundary. Home and End follow the browser's usual visual-line behavior.

### P1. Clipboard, keyboard access, and input methods

- Copy an entire visible link label, then paste into the plain Markdown editor. Expect the self-contained Markdown link, including its title and label styles. Copy just `oc` inside `[D**oc**s](/docs)`. Expect the standalone `**oc**`. A selection that clips a label and continues into prose preserves visible text and eligible local styles. Include the URL only when the whole label is selected or when the selection explicitly includes it in source editing.
- Cut the same selections in both directions. The clipboard matches Copy, the edit follows the visible deletion rules, and one Undo restores the source and selection. Select All still copies or cuts the exact note, including hidden syntax. In source editing, Copy and Cut use the explicit raw range.
- Paste multiline Markdown from a plain clipboard and preserve the current CRLF-to-LF handling for incoming paste. HTML-only content must never write arbitrary browser DOM into the note. A paste over plain selected text creates a link only for a single valid URL and an eligible selection. Choosing Paste as plain text inserts source characters at the caret. A URL pasted with no selection remains ordinary input.
- Start composition in ordinary text beside a link and separately over a backward selection inside a styled label. Update the composing text, confirm it, then Undo. It appears once in the correct field, and Undo restores the original selection. Arrow keys and Escape used by the IME should reach the IME. Cancel composition without altering the saved note. Repeat at wrap and line boundaries.
- Use mobile autocorrect, desktop spellcheck replacement, dictation, and drag-and-drop on a word beside a link. Use the browser's actual replacement range when it supplies one. The replacement enters the intended field once, even when the visible live caret is elsewhere. A move within the editor removes the original range exactly once. If the browser supplies an input that Zen cannot reconcile safely, preserve the document and avoid leaving the DOM ahead of the model.
- Open the toolbar with the existing Alt+F10 path. Move among enabled buttons with arrows, use Enter, and return to the original selection with Escape. Expose active and mixed styles to assistive technology. The editor's Tab indentation must have a documented keyboard path to move focus out. A collapsed caret outside a link must not open a popup or steal focus.
- On touch, select a partial label with native handles and use a formatting control. Keep the selected range, position the popup within the visible viewport as the keyboard opens, and allow a tap away to place a new caret. Verify screen reader output for a completed link and for literal syntax. Markers hidden from the visual editor should also be absent from its spoken text.

### P1. Undo, views, and document scope

1. Type a link in order and exercise Undo and Redo across the keystroke that completes it. Restore the source and selection for each history state. Navigation creates no history entries. Typing groups end at a caret move or command, and a formatting action, paste, IME commit, or URL submission is one undoable step.
2. Apply Bold to a backward selection inside a link. Undo restores the previous Markdown and the backward selection. Redo restores the formatted Markdown and the same visible selection. Repeat for Delete, URL editing, and the creation of a link from a clipboard URL. A new edit after Undo clears the redo branch.
3. Switch Zen Write to Preview and back with a caret inside a completed label and separately with a backward selection across marks. The selection returns to its original source position, the viewport stays near the writing position, and no edit is queued. Move between Zen and the plain Markdown editor as well. Preserve source offsets where they map to visible text. When transitioning from a raw offset inside a hidden URL, use the link’s outside edge and keep the saved source intact.
4. Switch to a different note, receive a new snapshot, and lock the vault in separate runs. End pending marks and popup interactions for the old document. Undo in the new document cannot replay changes from the old one.
5. In a long note, type inside a link, move across adjacent styles, select multiple wrapped lines, and delete near the first and last line. Keep unaffected line nodes and preserve existing caret scroll and reduced-motion behavior. Neither caret movement nor a single ordinary character edit should join or re-lex the entire note.

### P1. Fill pretyped formatting pairs

1. Type `Say ****` with the caret after the fourth asterisk. Press Left twice to reach `Say **|**`. Type `two words` one character at a time. Keep the caret between the pairs even after the first letter makes the span parse. Press Right twice to leave the pair. The source is `Say **two words**`, and only the two words display as bold.
2. Repeat with `Say **` for italic, `Say ~~~~` for strikethrough, and two backticks after `Say ` for inline code. Move left one character for single-character delimiters and twice for double-character delimiters. Inside the code pair, type `[x](/url)`. When you leave, the text displays as code, and clicking it edits literal text.
3. Inside a revealed bold pair, type an italic pair, move inside it, and fill its text. Move Right across both closing runs. All source characters remain reachable until you leave the outer pair. After it collapses, Left reaches the last visible grapheme in one press. Type outside to verify that neither style leaks.
4. Type an opening marker, then text, then the closing marker at the end of a line. Rendering still happens on the last keystroke. Repeat with an escaped opener, unmatched runs, triple asterisks around a word, and four asterisks on a line by themselves. Treat literal or structural Markdown according to its parse and keep ambiguous offsets reachable as source.

## Refactor sequence

1. **Keep incomplete links literal.** Require a visible label and allowed destination before hiding link syntax. Verify ordinary typing, complete Markdown pasted or loaded from a note, and creation through the Link action. Check that literal bracket and parenthesis text remains editable without introducing link-specific draft state. Preserve the selection when rendering the edited line.
2. **Share boundary and selection rules.** Route mapping, visible range edits, link targeting, and clipboard selection through the same description of the line. Use canonical outside positions for hidden delimiters and preserve exact offsets for exposed source. Keep ordinary navigation native where the browser produces the specified movement. Add a visible fallback for unsupported syntax and track fence context from affected lines so code stays literal.
3. **Apply the same edit rules across entry points.** Use parsed spans for Code and the existing formatting serializer where it already preserves the intended result. Reuse the selection mapping for pending marks, cut, paste, composition, replacement, and popup edits. Capture before and after selection in the history transaction and retain the existing history bound. Keep the [source adapter](internal/web/static/js/editor/source-adapter.js) responsible for handing off raw text and selection between editors.
4. **Verify through both browser paths.** Add incremental-keyboard cases to [the static Zen fixture](test/browser/zen-inline-toolbar.spec.js) and note persistence, focus, and view round-trips to [the app Zen suite](test/browser/zen-mode.spec.js). In each test, assert saved Markdown, visible text and marks, selection direction or caret affinity, and the placement of the next typed character. Include Chromium and Firefox, plus real macOS and mobile Safari checks for platform keys, composition, touch handles, and clipboard behavior. Use focused policy tests for parser ranges and mapping, and keep the large-note regression for unaffected line identity.
